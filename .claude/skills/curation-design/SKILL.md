# 대외활동 큐레이션 디자인

이 서비스의 화면은 이 문서의 규칙을 따른다. 새 화면을 만들 때는 이 토큰과 컴포넌트를 그대로 쓰고,
다 만든 뒤에는 아래 체크리스트로 의도에 맞는지 점검한다. 실제 예시는 `design/시안.html`에 있다.

## 방향 한 줄

콘텐츠(공고)가 주인공. 배경은 클린 뉴트럴, 카드는 흰색, 보라는 브랜드 액센트로만 절제해서 쓴다.
토스처럼 친근하되 신뢰감 있는 "도구". 진로·기회·장학을 다루니 믿을 만한 느낌이 핵심이다.
상태(가능·불가·확인 필요)는 색으로 한눈에 구분되게 한다.

## 원칙 (토스 톤, 단 우리 룰·변수 유지)

- 배경은 뉴트럴(연회색), 카드는 흰색 + 은은한 테두리. 전면 보라 배경은 안 쓴다.
- 보라는 액센트로만. 로고·주요 버튼·선택된 필터·링크·AI 강조에만. 사방에 깔지 않는다.
- 모서리는 절제(카드 16px). 통통한 22px·전부 알약은 지양. 칩·둥근 버튼만 알약.
- 글꼴은 깔끔한 모던 산세리프(Pretendard 계열). 둥근 Nunito·캐릭터 톤은 걷어냈다.
- 위계를 세게. 제목은 크고 진하게, 기관·메타는 흐리게. 스캔되게 한다.
- 그림자는 은은한 뉴트럴 엘리베이션 + 1px 테두리. 무겁고 진한 보라 그림자는 안 쓴다.
- 상태 3색은 또렷하게 유지. 가능 초록, 불가 코랄, 확인 필요 앰버. 보라에 안 섞는다.
- 신뢰 신호를 담백하게: 규모(공고 수)·신선도(수집 시각)·출처를 은근히 보여준다.

## 색 토큰

새 화면은 이 변수만 쓴다. 임의 색을 새로 만들지 않는다.

실제 앱은 App.css에서 같은 값을 `--violet`(브랜드)·`--page`·`--ink` 등으로 쓴다. 아래는 그 원본.

```css
:root {
  /* 브랜드 보라 (액센트로만) */
  --purple: #6c4dff;
  --purple-hover: #5b3af0;
  --purple-soft: #f2eeff;   /* 아주 연한 보라(선택·근거박스) */
  --purple-chip: #ede7ff;
  --brand-line: #e4dcff;    /* 보라 액센트 테두리 */

  /* 뉴트럴 (콘텐츠가 주인공) */
  --page: #f6f7f9;          /* 페이지 배경(연회색) */
  --card: #ffffff;          /* 카드 */
  --line: #eaecef;          /* 카드 테두리 */
  --line-strong: #dde1e6;   /* 입력 테두리·호버 */
  --ink: #191f28;           /* 기본 글자(뉴트럴 다크) */
  --ink-2: #4e5968;         /* 보조 글자 */
  --muted: #8b95a1;         /* 흐린 글자 */

  /* 상태 3색 (정제, 의미 유지) */
  --ok: #12b886;      --ok-bg: #e6f8f1;     /* 지원 가능 */
  --no: #fa5252;      --no-bg: #ffecec;     /* 불가 / 마감 임박 */
  --review: #f59f00;  --review-bg: #fff6e5; /* 확인 필요 */
}
```

## 모서리 / 그림자 / 글꼴

```css
--r-card: 16px;   /* 카드·패널·입력창(절제) */
--r-input: 12px;  /* 입력·주요 버튼 */
--r-pill: 999px;  /* 칩·필터 */
--shadow-sm: 0 1px 2px rgba(23,31,40,.06);
--shadow: 0 1px 3px rgba(23,31,40,.08), 0 8px 24px rgba(23,31,40,.05);
```

글꼴은 깔끔한 모던 산세리프. `-apple-system, "Pretendard", "Apple SD Gothic Neo", sans-serif`. 제목은 굵게(800), 자간 살짝 좁게(-.02~-.03em).

## 컴포넌트 패턴

- 상단 바: 흰 배경 알약, 왼쪽 브랜드(원형 그라데이션 점 + 이름), 오른쪽 보라 알약 버튼.
- 히어로: 라이트. 크고 진한 제목 + 흐린 부제 + 신뢰 칩(초록 점 · 공고 수 · 수집 시각). 다크 카드·캐릭터 없음.
- 조건 입력: 흰 카드 패널 + 은은한 테두리. 라벨 위 필드, 안 고른 건 흐린 글자.
- 결과 섹션: 섹션마다 상태 칩(색 점 + 이름) + 개수. 그 아래 흰 카드 목록.
- 결과 카드: 위에 카테고리 칩과 D-day(임박은 코랄), 굵은 제목, 주최, 연한 근거 박스.
- 조건 1개 차이 카드: 코랄 테두리, "이것만 바꾸면 가능" 배지, 요구값과 내값 비교, 바로 고치기 버튼.

## 점검 체크리스트

디자인을 만든 뒤 이걸로 확인한다. 하나라도 아니오면 고친다.

- 보라가 주인공인가. 흰색이 주인공처럼 넓게 깔리지 않았나.
- 모서리가 다 둥근가. 각진 요소가 없나.
- 가능·불가·확인 필요가 색으로 바로 구분되나. 셋 다 보라에 묻히지 않았나.
- 흰 카드 위 글자가 잘 읽히나. 대비가 충분한가.
- 문구가 딱딱하지 않고 말 거는 느낌인가.
- 위 토큰 밖의 임의 색을 쓰지 않았나.
- 근거 문장이 보이나. 왜 이렇게 판정했는지 사용자가 알 수 있나.

## 마음에 안 들 때 (반복하는 법)

이 스킬을 고정된 규칙으로 두지 말고, 결과가 마음에 안 들면 이 문서를 고친다.
예를 들어 보라가 너무 연하면 `--purple` 값을 바꾸고, 캐릭터를 더 키우고 싶으면 히어로 패턴에 크기를 적어 둔다.
바꾼 규칙으로 화면을 다시 만들어 보고, 될 때까지 문서와 화면을 같이 굴린다.
